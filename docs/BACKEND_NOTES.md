# 桌面运行与本地恢复

## 计时

主进程用 `performance.now()` 计算有效用时。运行中约每 250 毫秒推送快照，并在下一阶段边界额外唤醒。待命、暂停或完成后仅在状态变化时广播。预览与出击共用 `compileTimeline`。暂停、绝招和放弃以命令执行时的同一次时钟读数判定阶段。

每两秒写入会话检查点。阶段切换、出击、暂停、继续、绝招、完成和放弃立即写入。完成与绝招在保存成功后触发演出。持续五秒写入失败或保存尚未返回时冻结进度。恢复写入后可以手动继续。

已锁屏时抑制演出事件。按用户设置暂停锁屏计时，收到睡眠通知则始终暂停。仅收到唤醒通知时使用最近一次成功保存的检查点。应用重启后将未结束的会话置为暂停。Windows 收到注销或重启的会话结束通知时立即尝试保存当前进度，并允许系统继续注销。系统强制结束进程时使用最近一次已完成的检查点。

## 数据

应用在 Electron 的 `userData` 目录维护四份记录。每份文件含 `schemaVersion: 1` 和 `data`。

| 文件 | 内容 |
| --- | --- |
| preferences.json | 桌面、声音、运行和快捷键设置及设置版本 |
| presets.json | 用户预设、选中编号和本次预设操作的设置版本 |
| session.json | 本局时间线、有效用时、状态及已用绝招，放弃后为 null |
| window-state.json | 窗口逻辑坐标、显示器、尺寸、可见性和首次穿透提示标记 |

预设与选择在同一个文件内原子提交。启动时采用两个设置文件中较新版本的选择。内置预设随程序提供。文件更新先在同一目录写临时文件并同步，再原子替换正式文件。上一份有效记录保存为 `.bak`。不合规范的文件保留为 `.corrupt-唯一编号`，随后尝试备份。无有效会话时回到待命。目录同步能力依赖主机文件系统。

## 窗口与交互

桌宠关闭后台节流以接收隐藏期间的声音事件，渲染端负责在隐藏时停下模型及夜雨动画。控制窗和中央结算窗启用正常节流。再次打开已存在的控制窗会聚焦原窗口。打开当前设置页保留草稿，离开已编辑的节奏页会出现保存或放弃选项。桌宠与结算窗均不可聚焦。主屏可用区决定首次位置，保存的显示器断开后重新限制坐标。X11 使用指针移动采样辅助命中判断，Windows 和 macOS 使用原生鼠标转发。

主进程只接受受信顶层窗口的固定命令。桌宠可请求命中、拖动、绝招、右键菜单和打开控制窗。控制窗负责会话及设置。中央横幅只读。单个请求的重发由请求编号去重，保留最近 100 条已处理结果。资源协议 `app://assets/` 只读取有效资源目录内的普通文件，路径按真实文件位置校验。

开发构建可用绝对路径环境变量 `NIGHTREIGN_USER_DATA` 指定独立测试目录。打包构建使用系统应用数据目录。Linux 明确报告开机启动不受支持。快捷键通过系统 API 注册，失败时恢复旧绑定。目标平台的多显示器、睡眠通知和开机启动仍须由 Windows 与 macOS 实机验收。

可控时钟、存储故障和应用端到端验证见 [测试方案](TEST_PLAN.md) 与 [测试报告](TEST_REPORT.md)。
