# 小蜗桌宠第一版测试方案

验收依据为 [产品规格](../SPEC.md)、[技术架构](TECHNICAL_DESIGN.md) 和实现契约。每项在测试报告中记为通过、失败、受阻或待实机验证，并注明所用构建和测试环境。真实小蜗资源、Windows 实机和 macOS 实机均是发行验收的必要证据。

## 测试层级

| 层级 | 工具与方法 | 通过证据 |
| --- | --- | --- |
| 核心 | Vitest，使用自定义可控单调时钟和独立构造的时间线 | 每个边界、有效时间、设置规则和状态转换均符合规格 |
| 主进程集成 | Vitest，临时 userData、可控系统事件及文件故障 | IPC 验证、串行命令、保存恢复和系统失败的可重现结果 |
| 桌面端到端 | Playwright Electron，真实窗口和独立 userData | 从可见入口操作，核对窗口、界面、文件和退出重启结果 |
| 真实运行 | 默认预设，进程持续运行 40 分钟，独立单调计时 | 自动推进 11 阶段，成功一次，端到端误差不超过 1 秒 |
| 目标平台 | Windows 与 macOS 的打包应用和真实桌面 | 平台窗口、音频、系统事件、安装和完整流程均有记录 |

核心断言使用规格中的预期值。可控时间用于毫秒级边界和异常路径，桌面快速流程使用 11 个一秒阶段的合法自定义预设。真实 40 分钟流程按默认预设、真实时钟和发布路径运行。测试适配器限于测试进程或独立入口。

## 时间线与会话

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| CLK-01 | 默认 11 阶段 | 阶段起点为 0、270、450、660、840、1020、1290、1470、1680、1860、2100 秒。逐项检查边界前 1 毫秒、边界和边界后 1 毫秒。2400 秒成功，后续推进保持同一次结算 |
| CLK-02 | 适配课长 | 31:00 得到 `[60, 60, 60]`，31:01 得到 `[60, 60, 61]`，31:15 得到 `[60, 60, 75]`，32:06 得到 `[62, 82, 102]`，40:00 得到 `[180, 240, 300]`，45:00 得到 `[255, 340, 425]`。31–180 分钟内各场至少 60 秒，秒数之和精确等于目标减 1680 |
| CLK-03 | 原作与自定义 | 调整原作夜晚时长后两天的四段依然固定。自定义各输入独立生效，最小合法总时长 11 秒，180 分钟可保存，超出 1 秒被拒绝。覆盖零、负数、小数、空值、非法文本和非有限数 |
| CLK-04 | 暂停与继续 | 暂停点的用时和战斗血条冻结，暂停超过 60 秒后继续，下一边界仅由剩余有效时间决定。多次暂停相加后仍正确。系统日期前后跳变时累计时间连续 |
| CLK-05 | 主线程阻塞与状态订阅 | 单次唤醒跨多个阶段直接呈现当前阶段，过期提示不补播，播放事件不重复。剩余时间保持非负。新窗口读取最新状态，过期快照不使画面倒退 |
| CLK-06 | 并发和绝招 | 双击出击只建一局。命令重放不重播事件。普通阶段、暂停和旧阶段请求拒绝绝招。三场各可使用一次，恢复后保持使用记录。精确边界先推进，绝招前后血条和阶段终点一致 |
| CLK-07 | 结束与再次出击 | 运行或暂停中取消结束维持原状，确认后待命且没有胜利。自然完成后摘要可收起和重新打开，再次出击使用当前选定预设且只创建一局 |
| CLK-08 | 预设隔离与 40 分钟实跑 | 调整、改名或删除当前预设后，本局各节点仍按出击时的快照运行，下局使用当前选定预设。实跑保持应用开启、不暂停、从可见出击入口启动。记录全阶段、成功次数和独立时钟误差 |

## 设置、交互与演出

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| UI-01 | 首次启动和出击准备 | 主屏可用区右下角出现桌宠。控制页展示预设、总时长、模式、五段摘要和可展开的缩圈时间线。出击关闭准备界面并出现 `DAY 1`，隐藏或关闭设置时计时继续 |
| UI-02 | 设置页和输入反馈 | 四页可到达。每页恢复默认前有确认且只影响本页。验证时间页预览、保存、未保存离开时保存或放弃、非法输入及下局生效提示。预设可保存、改名、删除，内置预设不可删除，删除所选预设回到内置 |
| UI-03 | 桌宠操作 | 轻触与拖动的结果不同。拖动结束不打开准备页，锁定后仍可点击。大小 50% 与 200% 下模型和控制完整，置顶切换即时生效。隐藏、精简和详细状态条分别显示正确内容 |
| UI-04 | 状态与战斗 | 进度提示含阶段或下一事件，缩圈时展示结束倒计时，详细模式显示总剩余。三场显示对应血条，血量单调降至结束。阶段标题自动淡出，胜利显示准确的 `NIGHTLORD SLAIN` 并回待命。夜雨和结算范围局部，未改变其他窗口位置 |
| PET-01 | 人物手势 | 在第一夜双击人物，只消耗本场一次绝招。单击、拖动、暂停、穿透、透明区域和计时栏分别操作后检查使用记录。出击面板的 Alt+U 遵守相同的战斗条件，弹出确认框时停用。 |
| PET-02 | 看向鼠标 | 在真实模型上把鼠标从右下移到左上，检查目光、侧倾和俯仰方向。移开后回到当前待机曲线，开启穿透或安静模式后保持该曲线。 |
| PET-03 | 不死行军 | 在 Cubism Core 中检查蓄势、哀叹、波纹和收势的可见网格，核对两套绝招均隐藏琴和召唤灵。用桌宠实录检查脚底位置、面部和光波。 |
| UI-05 | 声音与演出 | 总静音覆盖所有通道，音量保留。音效试听可触发，缩圈开关控制文字与声音，光环仍推进。无音乐资源时显示原因。低、标准、强演出有区别。退出安静模式恢复原音量和演出。演出预览不创建会话或消耗绝招，真实转场可接管预览。暂停冻结战斗声音与进度，隐藏桌宠时声音继续 |
| UI-06 | 用户找回与退出确认 | 桌宠右键及托盘或菜单栏操作与状态匹配。验证暂停、继续、静音、安静、状态条、锁定、穿透、设置、结束和退出。首次开启穿透提示找回入口，从托盘恢复、显示桌宠、重置位置。取消退出维持会话，确认退出保存后关闭 |
| UI-07 | 键盘和可读性 | 键盘可访问控制页主要操作、各设置页、开关与确认框，焦点可见并回到合理位置。Tab 顺序与显示顺序相符，表单、提示有可理解的标签。窄窗口与系统 200% 缩放时主要操作可见。焦点留在外部应用期间，桌宠演出和结算不截获输入 |
| UI-08 | 全局快捷键和开机启动 | 分别配置四类快捷键并触发，验证修改和注销。已有占用导致绑定失败且旧设置仍可用。非法快捷键有解释。开机启动成功与失败均如实显示，重启后读取真实系统状态 |

## 中断、数据和 IPC

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| REC-01 | 锁屏与睡眠 | 默认锁屏冻结，解锁待继续。关闭锁屏暂停后推进至当前阶段，不补播历史提示，若已结束可读结算。睡眠总暂停，唤醒待继续。缺失 suspend 通知时回到最近成功检查点并暂停，记录回退量 |
| REC-02 | 优雅退出与强杀 | 运行中退出并等待后重启，恢复界面时间冻结。继续与放弃分别验证。进程被强杀时，正常存储下回退不超过 5 秒，恢复后已使用绝招仍不可用。离线超过总时长也从保存时刻暂停恢复 |
| REC-03 | 渲染进程故障 | 模拟桌宠渲染器停止，主进程暂停并保存，重建后等待继续。控制窗口渲染器退出时计时继续，重新打开读取最新状态。阻塞或隐藏普通渲染不影响时钟 |
| DATA-01 | 重启与迁移 | 四类本地数据分别核对。旧版本样本按已定义兼容策略读取或迁移。错版本、空值、截断 JSON、无效会话或时间线采用有效备份或受控默认值。孤立临时文件不会覆盖正式数据 |
| DATA-02 | 写入故障 | 注入临时文件写失败、替换失败和连续检查点失败。有效旧文件仍可读取。关键命令不提前确认。超过 5 秒自动暂停并提示重试。恢复写权限后能保存并确认。并发更新后序号、备份和最终文件一致。Windows 占用和两端异常终止另在实机验证 |
| IPC-01 | 权限与能力范围 | 控制、桌宠和结算窗口仅暴露各自方法。验证沙箱与上下文隔离、禁用 Node 集成、限制导航与新窗口。渲染器无法通过现有接口要求任意文件读取、任意频道或另一窗口专属命令 |
| IPC-02 | 负面输入与陈旧状态 | 拒绝缺失字段、未知命令、非法 enum、非有限或超范围数字、旧会话和旧阶段。正确请求之后还能正常完成。版本冲突提示刷新，过期写操作不覆盖新值。相同请求 ID 去重 |
| WIN-01 | 屏幕变化 | 在外接屏关闭并重开保留位置。断开外接屏后桌宠、控制和中央结算区域回到可见工作区。交叉验证多 DPI、负坐标、任务栏和 Dock 的可用区域 |

## 模型、资源与长期运行

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| ASSET-01 | 小蜗身份与随包资源 | 记录来源、授权和角色身份。清单指向实际 `.model3.json`、`.moc3`、贴图与模型依赖，声明 SDK 兼容和实际可演出动作。在打包应用中离线加载、看到可动小蜗。缺失、未授权或无法确认的小蜗模型均判成品验收失败，SDK 样例仅用于兼容测试 |
| ASSET-02 | 失败与重试 | 分别模拟缺少清单、模型文件、Core、贴图及包含越界引用。应用显示具体问题并保留计时、设置、托盘入口。恢复有效资产后可重试。动作缺失按显式映射降级，时间照常推进 |
| ASSET-03 | 渲染资源释放 | 验证 Live2D WebGL 上下文丢失并恢复、反复显示隐藏、重新创建桌宠渲染器、重试加载、打开关闭控制和中央横幅。记录 Canvas、渲染器和模型实例数的变化。重复 20 轮后检查旧模型、纹理、动画循环和窗口已释放。缺真实资产时该部分保持受阻 |
| PERF-01 | 资源采样 | 分别采待机、探索、强演出、隐藏四态，每态稳定 30 秒以上、每秒采样。记录系统/架构、CPU、内存、GPU、分辨率/DPR、Electron 版本和模型尺寸，报告渲染帧率、进程 CPU、RSS、GPU 和功耗的可测数据及采样工具。区分可获得的进程 RSS 与系统物理内存，未测量字段明确标注 |
| PERF-02 | 40 分钟稳定性 | 运行期间记录 RSS 变化、窗口数量、渲染器错误、掉帧、阶段误差与一次成功。通过隐藏、恢复与窗口压力场景另测资源释放。未定预算时仅报告实测值 |
