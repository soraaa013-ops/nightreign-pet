# 技术选型更新目标

基线：2026-11-22。仅在下列触发条件发生时更新相关证据，不重新泛查整个技术生态。

| 目标 | 何时更新 | 核对内容 |
| --- | --- | --- |
| 实际小蜗资源 | 获取模型时 | 导出版本、动作、hit区域、贴图、可分发范围、匹配Core与Framework |
| Electron稳定版本 | 锁定依赖及每次升级时 | 透明窗与遮挡修复、两端powerMonitor事件、WebGL和后台音频 |
| Tauri替代路线 | Electron实测超预算或核心窗口能力受阻时 | 同模型对照、系统锁屏适配、WebView2与WKWebView、局部命中 |
| Open-LLM前端 | 需要借鉴SDK适配时 | 固定commit与新版本差异，不用旧教程覆盖当前源码 |
| AIRI主桌面与Kirie | 考虑宿主迁移时 | 是否真的完成新路线双端发行，Electron是否仍受支持 |
| DesktopMascot | 考虑复用Tauri窗口层时 | 公开Release、实际图形测试、错误处理和新SDK兼容 |
| Cubism与Pixi分支 | 模型升级或现有适配失败时 | Framework/Core/模型的兼容矩阵，区分原仓与现代分支 |
| 发布工具与资源条件 | 第一次发行或扩大模型导入范围前 | 稳定版本、签名公证、SDK发行条件与模型作者许可 |
| 性能预算 | 实际模型首次验证时 | 目标设备、同负载、完整进程树、内存CPU GPU功耗及隐藏行为 |

更新时保存新的来源文件与原子结论，报告写入 diffs/YYYY-MM-DD_delta.md，记录旧判断、变化证据和是否触发重选。不得把历史issue当成当前版本未修复，也不得把合入main直接当作所有稳定版本包含修复。
